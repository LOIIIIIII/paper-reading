0. 一句话结论

会生成逼真视频，不代表模型真的知道“世界现在是什么状态”。真正能做长时 hidden-state tracking 的架构，需要一个能跨视频块持续携带、并且可以被原地改写的内部状态。

1. 论文到底研究什么？

作者提出的问题不是“视频清不清楚”，而是：当一个关键状态在画面里消失以后，视频世界模型是否仍能在内部正确维护它，并随着动作继续更新。

可见状态→连续不可见→状态仍然变化→重新揭示

论文用最干净的实验把“视觉渲染”和“状态追踪”拆开：画面里只需要生成杯子的移动，但模型内部必须一直知道球在哪。

2. Shell Game：输入和输出是什么？

这是一个真正的动作条件视频生成任务。模型先看到 opening reveal，明确球初始在哪个杯子下；之后杯子落下，球完全不可见；输入动作序列指定每一轮交换哪两个杯子；模型自回归生成所有交换视频以及最后的 reveal。

(初始 reveal 视频 V₀, 动作序列 a₁:N) → 未来视频 V̂₁:N+1

但真正需要维护的是不可见状态：

s₀ --a₁→ s₁ --a₂→ s₂ --...→ sN

其中 s_t 表示“球当前在哪个杯子下面”。训练时只见 5 次 swap，测试会延长到 10、20、30 次。

3. S₃ 和 S₅ 是什么？

S₃ / S₅ 是对称群：分别表示 3 个元素、5 个元素的所有排列。S₅ 有 5! = 120 种排列。一次杯子交换就是一次 transposition；一串 swap 的本质，就是不断组合这些排列。

作者先在纯符号序列上做 S₃ / S₅ state-tracking probe，再把同一个问题视觉化成 5 杯 Shell Game。S₅ 的意义在于它对应更强的、顺序敏感的非交换状态组合问题。

4. 为什么标准 Transformer / Mamba / 线性注意力会失败？

训练长度 N=5 时，大多数模型都能拟合到很高准确率；但链长变成 10、20、30 后，状态准确率迅速掉到接近随机。与此同时，生成视频仍然很合理。

论文的判断：这些模型学到的是“短链怎么从整段历史直接映射到答案”的捷径，而不是可重复执行的单步状态更新规则。
捷径： [a₁, a₂, ..., a₅] → s₅

真正算法： s_{t+1} = F(s_t, a_t)

因此“视频质量”与“隐藏状态正确率”可以完全分离。

固定深度 Transformer / TC⁰ / NC¹ 的直觉：固定层数的模型可并行处理整段输入，但每增加一次互不交换的置换，正确答案都依赖此前状态。论文指出：在标准对数精度等假设下，一些固定深度骨干属于常数深度电路类 TC⁰；S₅ 的长链组合问题则是 NC¹-完全。若 TC⁰ ≠ NC¹，不能期望这种固定并行深度对任意长链稳定求解。这是特定计算模型下的理论动机，不等于“所有 Transformer 永远无法追踪状态”；外显 scratchpad 或足够表达力的递归更新会改变计算路径。见论文第 1 节。

5. KV cache 到底缺什么？

作者发现，Transformer 的自回归 KV cache 更像追加式视觉历史，而不是一个紧凑、可改写的 running state。

KV cache理想 running state
记录“过去发生过什么”直接表示“现在是什么”
append-only，旧 KV 写入后不改每来一个动作都原地更新状态
最后需要重新从历史推导当前排列直接读取当前状态即可

扩大 SWA 窗口能让模型在训练长度内看到全部交换历史，但不能解决长链外推，因为核心问题不是“看不到历史”，而是“没有把历史压成一个持续更新的当前状态”。

6. 成功机制一：GDN-neg

DeltaNet 风格模型本来就有矩阵状态 S_t，并进行递归更新。问题不是“没状态”，而是标准转移常限制为非负特征值，难以表示 swap 所需的带符号、类似反射的操作。

A_t = I - β_t k_t k_tᵀ

当 β 的范围允许产生负特征值后，可以实现类似 Householder reflection 的状态变换；而交换两个坐标本身就可以写成一种反射。因此：

GDN-neg 的本质：已有 persistent state，但把“状态更新算子”的表达能力增强到足以真正重排当前状态。

7. 成功机制二：LaCT / TTT fast weights

LaCT 的关键是把一个小型 SwiGLU MLP 的参数 W_t 当作工作记忆，并在测试过程跨 chunk 在线更新：

f_W(x) = W₁ [ silu(W₀x) ⊙ (W₂x) ]

W_t → W_{t+1}

这确实是在“改模型”，但改的是专门设计的 fast weights，不是永久重训整个大模型。这些 fast weights 就承担 hidden state 的角色。

尤其重要的是，更新作用于特征图 W₀、W₂，而不仅仅是最后的 readout W₁。这样历史会改变未来“如何读取/写入状态”的方式，使 effective kernel 具有历史依赖，而不是简单不断加关联。

8. 关键实验结论

N=5训练长度
标准骨干基本可拟合
→30长链外推
多数模型趋近随机
20%S₅ 五杯随机猜测基线
4→50增加去噪步数
不修复状态追踪

论文还做了内部 probe：普通自回归模型的当前读出很容易解码“现在交换的是哪两个杯子”，却很难解码“球现在在哪”；LaCT 和 GDN-neg 的 carried state 则保留了更强的隐藏球位置信息。

最简单理解：普通模型知道“现在画什么动作”，但不一定知道“隐藏世界现在是什么状态”。

9. 它和真实遮挡是什么关系？

Shell Game 不是自动驾驶遮挡本身，而是一个受控诊断实验：把“状态不可见但仍持续演化”抽象到最简单。

真实遮挡： visible → occluded → hidden dynamics → visible again

因此可以迁移的结论是：

不可观测状态需要 persistent state + expressive/revisable transition。

不能直接迁移的则是“负特征值/反射”这个具体技巧，因为真实车辆的 dynamics 不是杯子 permutation。

10. 对我们课题的启发

这篇论文主要解决“怎么存、怎么更新 hidden state”，但没有解决“这个不可见状态到底有没有被真实监督”。这恰好和同步多车训练监督形成衔接：

问题层本文我们的研究可继续做
状态容器persistent / revisable state可借鉴 LaCT、recurrent matrix state 等
状态更新强调 expressive transition设计适合驾驶 dynamics 的更新机制
隐藏区间监督像素扩散目标不能直接监督隐藏状态用同步多车/多视角在训练时提供 ego 看不到区域的真实证据
测试阶段单模型 rollout保持单车推理，多车仅作为 privileged training supervision
可形成的研究问题：“How can a single-view driving world model learn the evolution of states it cannot observe?” —— 用同步多视角为单车 world model 的监督空窗期提供真实跨视角证据。

11. 局限性与阅读时不要过度解读的地方

第一，Shell Game 是合成任务，不能直接证明所有真实世界视频模型都以同样方式失败。第二，GDN-neg 的 reflection 与 S₅ swap 高度匹配，不等于真实遮挡 dynamics 也应使用负特征值。第三，即使训练阶段有多视角真实监督，测试阶段若 ego 历史对隐藏未来本身信息不足，也不可能确定性知道真实随机行为，因此真实驾驶还需要不确定性或多模态 hidden-state prediction。
